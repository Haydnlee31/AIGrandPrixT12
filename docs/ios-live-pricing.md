# Amazon matching and live price checks

The native Library, Explore and Radar retain their local save flow. Explore and Radar now retrieve only reviewed Amazon Berkeley Objects records with a same-record ASIN, original marketplace and licensed photo. Each shopping action opens that exact marketplace's `/dp/ASIN`, never a title search or a substituted product. Historical catalog identity does not establish current availability.

Matching retains relevance order, prioritizes an explicitly saved Amazon ASIN and gates product subtypes. Explicit colors/materials cannot be satisfied merely by a shared style such as digital. The installed catalog has 147,702 ABO source records but only 28 WATCH source records. Missing Apple Watch/iPhone models return no close matches; landlines, headsets and ordinary watches are not replacements. On the final live check, a silver retro digital watch request returned one genuine silver digital watch, with its exact link and own photo.

## Live checks and tracking

- `POST /v1/price-check` accepts `product_url`. The private relay fetches the exact allowlisted Amazon page with bounded response size/time/concurrency and no redirects, cookies, login or challenge bypass. It verifies canonical/primary ASIN identity and reads only the main product's price-to-pay block. Ads, coupons, installment payments, used offers and conditional member prices cannot supply the amount.
- Results include `status`, exact `product_url`, `asin`, `marketplace`, integer `price_minor`, original `currency`, optional `reference_price_minor`/`reference_label`/`discount_percent`, `checked_at`, `basis`, and a short message. Shipping is excluded. Currency is never silently converted. Failure returns unavailable rather than a stale amount. Percentage reduction uses integer floor; MRP/List price is distinct from an observed historical drop.
- `POST /v1/price-watch` accepts `action` (`list`, `save`, `check`, `delete`), a stable installation `owner_id` UUID, and action-specific watch ID/link/title/target/currency. All actions return `watches`. This is the existing private development relay's access model, not production multi-account authentication.
- Explicit watches and up to 60 observations per watch persist in ignored `local-data/live-price-watches.db`. Storage is separate from Library. There are at most 50 watches per installation and 100 globally. Editing/deleting a watch invalidates in-flight older results. A failed attempt preserves prior history but clears current drop/target signals. Currency or price-basis changes cannot produce a false drop.
- A lifecycle-managed worker checks due watches at approximately 15-minute intervals while the relay remains running. It drains bounded batches with bounded concurrent fetches. Radar shows history, last-check time, target reached and changes from the previous comparable successful observation. Stop tracking deletes the watch/history. APNs/push notifications are not connected; updates appear when Radar loads or a person taps Check now.
- Product details and saved exact Amazon links show a live Price check panel. Tracking uses the offer's actual currency and a target slider based on that item's observed price. Radar's general shopping-budget slider adapts its UI range to product type and preserves existing choices. Its range is a control convenience, not a market-price estimate or a claim that unknown-price results meet a budget.

Authentication runs before parsing both new price endpoints. Request bodies are bounded to 8 KiB; responses use `Cache-Control: no-store`. Provider credentials remain in the ignored server environment, never the native bundle. Profile privacy explains explicitly stored price watches.

## Verified and limited

On 25 October 2026, live public Amazon.in listings returned INR6,300 vs MRP16,500 (61% conservative reduction) and INR6,800 vs MRP19,500 (65%). Another exact listing returned no primary offer; its sponsored prices were correctly ignored. A separate live HTTPS end-to-end check verified price, save, second observation, target detection, persisted list and deletion of an isolated test watch. These checks do not establish a naturally occurring live price drop.

The native panel rendered the real INR6,300/MRP16,500 check on Adi's physical iPhone. A subsequent physical-device screenshot showed Tracking price, the user's saved target and Price history. Xcode signed build and installation passed. Local Library's eight originals remained byte-equivalent before/after installation. The user confirmed that tracking saves and appears in Radar on the physical iPhone. A target-slider polish uses clean item-relative increments while preserving previously saved precise targets.

The final whole backend suite passed 646 tests, including live-discovery source/identity and accessory-exclusion regressions. Native checks cover local capture/grouping/source preservation, appearance, inline insight reduction, Radar persistence/matching, adaptive budgets, exact links, live-price decoding/currency/identity and 14 first-share lifecycle checks. Tests of historical drops and scheduled checks use controlled source observations; live prices and discount figures above were fetched from Amazon.

Public Amazon pages may block access or lack a primary price. The UI must retain that honest unavailable state. This is not Amazon Creators API access or a guaranteed live 200,000-product feed. The development Mac and its existing HTTPS tunnel must stay available for AI, retrieval and automated price checks. Teammates can replace the checker with an approved pricing provider without changing the native contract.

## Supplemental Amazon discovery

The ABO catalog has no Apple smartphones or Apple Watches. Explore and Radar now supplement uncovered product families with publicly accessible Amazon listings. Two source URLs discovered and verified on 25 October are indexed in `backend/app/amazon_listing_sources.json`; their primary ASIN, title and Amazon image are rechecked before display. Other families can use OpenAI web search source URLs. Generated prose URLs are ignored. No product facts, price or stock claims are accepted from generated text. Older models are presented as alternatives, not as the exact newer product saved.

The live HTTPS recommendations endpoint returned six products for the eight original saves in 2.87 seconds, including an Apple Watch Series 9 and iPhone 14 Pro with their own Amazon images. Digital watches are excluded from an explicit automatic/self-winding watch request. This is limited public-page coverage, not a comprehensive live Amazon catalog. Page blocks can still yield no verified results; no challenge bypass or unrelated-product padding is used. Discovery caches are bounded and short-lived; stored watch histories remain separate.
